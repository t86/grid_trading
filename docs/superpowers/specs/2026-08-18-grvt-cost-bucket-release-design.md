# GRVT 成本桶盈利退出与阈值亏损兜底设计

状态：已由用户确认。

## 目标

在不改变冻结账本、仓位上限、损耗上限和成交目标的前提下：

- 正常刷量按普通仓位入场成本桶盈利退出；
- 同一成本桶完成一次退出后，必须有新的同成本入场成交才能再次退出；
- 软阈值以下禁止交易所口径预计为负的普通减仓；
- 只有仓位超过软阈值时，才允许压力侧执行有界亏损减仓并恢复刷量。

## 范围

只修改 GRVT 当前四腿普通仓路径及通用 Hedge Mode 减仓容量核算。冻结仓位、冻结释放、终止排空、目标值和运行窗口不在本次范围内。不合并 `codex/arx-single-recovery-owner` 的完整恢复协调器。

## 成本桶与释放水位

普通入场成交按 `(position_side, entry_price)` 聚合为成本桶。每个桶保存累计入场数量和已授权释放水位。

- 新入场成交增加累计入场数量。
- 盈利减仓只能使用尚未越过释放水位的新增数量。
- 一次退出租约建立后，撤单、重报价和部分成交仍属于同一租约，不得生成第二个释放周期。
- 租约终结时，按实际成交数量推进释放水位；未成交数量不永久消耗水位。
- 没有新的同成本入场成交时，同一成本桶不得再次创建新的盈利减仓租约。

订单必须携带可审计的成本桶键、入场水位、租约 ID、成本价、盈利边界和数量上限。成交账本按这些字段精确消费对应成本桶，不能用其他价格桶补足。

## 盈利退出门禁

软阈值以下，普通减仓必须同时满足：

1. 订单价格相对成本桶成本至少盈利一个有效 step/tick；
2. 按当前交易所普通仓平均成本估算，成交后的 `realizedPnl >= 0`；
3. 数量不超过该成本桶当前未释放数量；
4. Hedge Mode 下，所有现存同侧平仓委托与新委托累计不超过交易所可减仓数量。

任一条件不满足时不创建普通减仓。普通开仓仍按现有四腿、anti-chase、预算和仓位上限规则运行。

## 超软阈值亏损兜底

只有某侧普通仓名义值达到或超过该侧软阈值时，才允许该压力侧进入现有 active-pair/pressure reduce 路径：

- LONG 压力只允许 SELL LONG reduce-only；
- SHORT 压力只允许 BUY SHORT reduce-only；
- 单个独立亏损减仓订单名义值不超过约 100U；
- 同侧独立亏损减仓订单间隔至少 60 秒；
- 优先使用可盈利减仓；只有无合格盈利订单时才使用买一/卖一亏损减仓；
- 仓位回到软阈值以下后立即关闭亏损授权；
- 不得消费、移动或冒充冻结仓位。

## 可复用改动

从 `codex/arx-single-recovery-owner` 仅移植 `89e50bfa` 的语义：Hedge Mode 依据 `positionSide + side` 识别现存平仓委托，即使 Binance 返回 `reduceOnly=false`，也必须占用对应侧可减仓容量。不得整体合并该分支。

## 失败与恢复

- 成本桶或租约元数据缺失、损坏或不一致时失败关闭该普通减仓，不影响普通开仓和另一侧合法订单。
- 账本同步失败时不签发新成本桶退出租约。
- 订单回执不确定时保留原租约，直到订单状态可证明终结；不能通过生成新 clientOrderId 绕过。
- 亏损兜底继续使用现有压力侧审计和冷却状态，不新增第二恢复所有者。

## 测试与验收

先写失败测试并确认 RED，再实现：

1. 同成本桶无新入场时，首次退出后第二次退出被阻止。
2. 同成本桶出现新入场成交后，只释放新增数量。
3. 撤单/重报价不创建新释放周期，部分成交只推进实际数量。
4. 成本桶盈利但预计交易所 `realizedPnl < 0`，软阈值以下不得减仓。
5. 超软阈值时只允许正确压力侧、约 100U、至少 60 秒的亏损减仓。
6. 回到软阈值以下立即关闭亏损授权。
7. Hedge Mode 现存 `reduceOnly=false` 平仓委托仍占用减仓容量。
8. 冻结订单和冻结账本行为保持不变。

114 canary 至少完成一个完整目标窗口后才考虑复制到 111。验收要求：

- 达到配置目标，量速不低于 111 同期；
- 干净普通成交占比不低于 80%；
- 万 U 负损耗不高于 111 同期；
- 无软阈值以下负 `realizedPnl` 普通减仓；
- 无“没有同成本补仓却再次同价减仓”；
- 无单笔超过约 100U 或间隔短于 60 秒的授权亏损减仓。
